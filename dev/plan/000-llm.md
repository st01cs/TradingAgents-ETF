# Specification: Deepchat LLM Provider Integration

## Project Overview

Add support for Deepchat as a new LLM provider in the TradingAgents-ETF project, enabling the use of DeepSeek's language models (deepseek-chat and deepseek-reasoner) alongside existing providers like OpenAI, Anthropic, and Google.

## Requirements Summary

### Core Models
- **Non-reasoning model**: `deepseek-chat` (mapped to `quick_thinking_llm`)
- **Reasoning model**: `deepseek-reasoner` (mapped to `deep_thinking_llm`)

### Key Characteristics
- Excellent Chinese language optimization
- Strong reasoning capabilities (especially deepseek-reasoner)
- Cost-effective compared to other providers
- Primary provider designation (not just backup)

## Technical Architecture

### 1. Integration Approach

#### Code Organization
- **Location**: Extend existing conditional logic in `tradingagents/graph/trading_graph.py`
- **Method**: Add new `elif` branch in the LLM initialization section
- **Pattern**: Follow existing provider implementation pattern

```python
# In trading_graph.py
elif self.config["llm_provider"].lower() == "deepchat":
    from langchain_deepseek import ChatDeepSeek
    self.deep_thinking_llm = ChatDeepSeek(
        model=self.config["deep_think_llm"],
        api_key=get_api_key(),
        **get_model_params("deep_thinking")
    )
    self.quick_thinking_llm = ChatDeepSeek(
        model=self.config["quick_think_llm"],
        api_key=get_api_key(),
        **get_model_params("quick_thinking")
    )
```

#### Dependency Management
- **Package**: `langchain-deepseek`
- **Installation**: Add to `pyproject.toml` dependencies
- **Version**: Use latest stable version

```toml
dependencies = [
    # ... existing dependencies
    "langchain-deepseek>=0.1.0",
]
```

**Installation Command**:

### 2. Configuration Management

#### Configuration File
- **Location**: `tradingagents/default_config.py`
- **Format**: Python dictionary (existing pattern)

```python
DEFAULT_CONFIG = {
```

### 3. Model Behavior

#### Model Mapping
- Fixed mapping strategy:
  - `quick_thinking_llm` ← `deepseek-chat`
  - `deep_thinking_llm` ← `deepseek-reasoner`

#### Usage Scenarios
- **deepseek-chat** (quick_thinking_llm):
  - Data analysis tasks
  - Simple queries and responses
  - Routine agent operations

- **deepseek-reasoner** (deep_thinking_llm):
  - Trading strategy generation
  - Complex reasoning tasks
  - Multi-step decision making

#### Reasoning Process Handling
- **Strategy**: Use final output only
- **Implementation**: Ignore intermediate reasoning steps
- **Justification**: Simplify integration, reduce latency

#### Model Selection
- **Approach**: Configuration-based (fixed mapping)
- **Runtime**: No dynamic switching
- **Flexibility**: Can change provider in config file

### 4. Error Handling & Retry Logic

#### Retry Strategy
- **Type**: Simple retry mechanism
- **Configuration**: Fixed 3 retries
- **Interval**: 1 second between retries

```python
# Pseudo-code for retry logic
max_retries = 3
retry_delay = 1  # second

for attempt in range(max_retries):
    try:
        response = llm.invoke(prompt)
        return response
    except Exception as e:
        if attempt < max_retries - 1:
            time.sleep(retry_delay)
        else:
            raise  # Re-raise after final retry
```

#### Exception Handling
- **Style**: Consistent with existing providers
- **Strategy**: Catch and log critical errors only
- **Failure Mode**: Raise exception after all retries exhausted
- **No Fallback**: Do not automatically switch to other providers

#### Error Classification
- **Critical Errors**: Server errors (500+), authentication failures
- **Logged**: All critical errors with appropriate log level
- **Silent**: Transient network errors (handled by retry)

### 5. Validation & Verification

#### Startup Validation
- **Type**: Format validation only
- **Check**: API key existence and format
- **No API Call**: Do not make actual API calls during startup
- **Error Handling**: Clear error message if API key is missing

```python
def validate_deepchat_config():
    api_key = os.getenv("DEEPSEEK_API_KEY")
    if not api_key:
        raise ValueError(
            "DEEPSEEK_API_KEY not found in environment. "
            "Please set it in your .env file."
        )
    if not api_key.startswith("sk-"):
        logger.warning("DEEPSEEK_API_KEY format may be incorrect")
```

#### Validation Timing
- **Development**: Validate on startup
- **Production**: Validate on startup
- **Manual**: No manual validation command needed

### 6. Logging Strategy

#### Development Environment
- **Level**: DEBUG
- **Content**: Full request/response logging, including prompts
- **Purpose**: Facilitate debugging and development

#### Production Environment
- **Level**: Minimal (ERROR only)
- **Content**: Only log errors and critical failures
- **Performance**: No performance overhead from logging

#### Log Format
- **Style**: Consistent with existing providers
- **Information**: Timestamp, error type, error message, stack trace (for errors)
